# Title tags

Load for a title/search-snippet problem. Inspect the actual page answer, query
intent, current title/H1/canonical, language and available search evidence.
Titles should help a reader recognize the answer, not promise an unsupported one.

## Diagnose the mismatch

Is the title vague, stale, repetitive, wrong-language, stuffed with synonyms,
about a different task or unsupported by the body? Low CTR alone isn't diagnosis:
position, result features, device, query mix and period can differ. Compare like
contexts where data exists and keep missing evidence explicit.

[Google's title-link guidance](https://developers.google.com/search/docs/appearance/title-link)
explains that title links can use several page/link sources, recommends useful
descriptive titles and warns about inconsistent or stale text. There is no fixed
character limit that guarantees display; truncation depends on the presentation.
Source checked 14 October 2026; verify current guidance for a new technical claim.

## Draft around the actual answer

Use the recognizable task/topic and necessary distinction. Keep the brand where
helpful without making every title identical. Align title/H1 with the page job,
not necessarily exact text equality. Avoid gratuitous dates, “best,” numbers or
claims the page cannot support.

For a fictional page that explains invitation expiry and resend, “Recover an
expired invitation” fits better than “Invitations made easy.” Don't title it
“Fix every login issue” or manufacture five duplicate variants as new pages.

Deliver a recommended title, why it fits reader/query/page, any useful alternative
tradeoff and source/metadata owner. Code verifies actual metadata under authority;
Writing owns expression and SEO canonical intent. A proposed title is not a live
search result or ranking improvement. Preserve useful URLs and surrounding
metadata unless a distinct correction is justified.
