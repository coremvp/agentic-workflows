# SEO

Help the right reader find a useful, truthful answer. Search intent and ownership
are distinct from [Marketing's](../marketing/SKILL.md) argument, [Writing's](../writing/SKILL.md)
expression and [Product's](../product/SKILL.md) capability truth. Source/config
defaults do not establish the founder's market or keyword demand.

## Decide whether a page earns the work

Start with the reader's question, situation and next useful action. Inspect
supplied feedback and current search results when the decision depends on them;
record source/date/context and distinguish a query hypothesis from measured
demand. No invented search volume, difficulty, traffic or ranking forecasts.

Before adding a URL, inspect existing Docs, Blog and product pages for the
canonical answer. Improve an existing owner when it can satisfy the intent.
A new page needs a distinct reader job and value gap; synonymous queries do not
justify duplicate pages. Do not turn each feature or keyword into an article.

Keep the small search contract in the existing brief: reader/question and intent,
existing owner or justified new page, useful answer and evidence, next action,
indexability intent and material unknowns. Ask through Lead when audience or
ownership changes the result. Search relevance cannot authorize new capabilities
or unsupported promises. Technical content must help someone use or decide,
not just lead them to another thin page.

## Use this repository's real discoverability owners

For an actual problem, name the symptom and evidence representation before a
fix. Inspect access/status, intended discovery/indexability and canonical/locale
ownership where they can explain it, then the delivered answer, intent and
presentation. A blocked or wrong canonical answer may need repair before title
polish. A bounded content request does not require a whole-site audit. Use
[Audit](references/audit.md) for the ordered method and select only relevant layers.

Inspect the actual public content/routes and installed framework before changing
APIs. Use compatible current first-party guidance for version-dependent behavior.
Find the host's brand/origin/locale configuration, public metadata/canonical
helpers, URL inventory/crawler instructions, content schemas, gated readers and
any machine-readable discovery owner. Reuse their authority instead of a second
SEO/content corpus. This package supplies no framework-specific file map.

Check title/description/canonical/image against the rendered page's job and
actual origin. Public indexability is an explicit decision. Auth/dashboard,
checkout, invitation and private/gated material must not leak into public
inventory or previews. Robots directives are not authorization; server access
boundaries still require their real owner and proof.

Structured data describes what the page actually contains, not invented ratings,
offers or credentials. Alt text and social previews should truthfully describe
their asset. A missing image/file, redirect, wrong origin, duplicate canonical
or inaccessible answer can invalidate a discoverable page even with good copy.
Frontend owns consequential visual changes; SEO does not bypass its agreement.

## Verify and learn within the assignment

Code alone runs applicable MDX/schema/metadata checks or route/browser proof.
Review reads the brief, actual artifact/source and Code's evidence independently.
Select the smallest check through the real owner, including a relevant reject
case when indexability/access is changed. Package source inspection is not live
crawling, provider indexing or ranking proof.

Use actual search/customer response when available, retaining baseline/time and
attribution limits. Distinguish discovered, crawled, indexed, ranked and converted;
one does not establish the next. No analytics installation, ongoing monitor,
vendor call or outreach is implied. Taste's feedback method can retain a
consequential scoped lesson; a proposed effect remains a hypothesis.

Return the recommended owner/change, reason, evidence, missing inputs and actual
proof/limits. Ordinary content work uses Writing and existing actors, not a new
SEO procedure or engineering cycle. Runtime/metadata code changes use Development
and the applicable technical owners under human implementation authority.
