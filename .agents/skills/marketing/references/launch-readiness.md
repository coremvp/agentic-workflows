# Launch readiness

Load when communication depends on an unresolved release condition. Keep a
bounded readiness record in the existing task, not a second release system.
Check only surfaces needed for the actual audience and promised action.

## Before the change

Bind claims to Product/source facts, target release/version, eligibility, flags,
setup and known limits. Name the release owner, actual authorized environment,
observable finish, failure/recovery owner and hold condition. Inventory required
assets, rights and public/private boundaries. A demo capture is not a provider
or permission check.

For each condition record owner, evidence needed, state (proved, missing,
not_run) and consequence. Existing automation should own repeatable technical
checks; Marketing specifies the communication dependency and requests Code's
actual evidence, not self-declared technical proof.

## At the communication boundary

| Promised path | Necessary evidence / owner |
| --- | --- |
| Open a page | Correct destination/status/access/canonical; Code + SEO |
| Submit a form | Validation, safe recovery, real durable result; Development/Code |
| Use an eligible feature | Actual eligibility and supported behavior; Product + Code |
| Follow setup | Literal supported guide and starting state; Writing + Code |
| Judge a visual/motion asset | Actual render/playback and truthful capture; Taste/Code |
| Find release through search/social | Relevant metadata, preview and public inventory; SEO/Code |

Check applicable desktop/mobile/accessibility through the actual visual owner
when UI changes are authorized. Do not make a marketing checklist permission for
an application redesign. Use existing technical evidence when inputs are
unchanged; an announcement edit does not justify rerunning a provider.

Hold an unsupported claim or action until its dependency is resolved. Prepare
copy that truthfully describes available beta/limits where that is useful. A
missing checkout proof cannot be repaired by calling a preview “ready.”

## Follow up proportionately

Identify where failure would be observed, who can withdraw/correct communication,
and which authorized owner handles rollback/recovery. Never restart services or
mutate production from this guide. After release, inspect actual broken links,
support questions and the chosen outcome signal, preserving attribution limits.
Repair the important mismatch through its owner before creating more content.
A plan, green source review and an unrun check are distinct evidence states.
