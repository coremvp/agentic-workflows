# Content promotion

Load when an existing asset needs a useful encounter path, or several assets
must work together. Ordinary selection of one channel stays in Marketing.
Promotion decides jobs and sequence; Writing's [repurposing](../../writing/references/repurposing.md)
changes expression without weakening proof.

## Give each encounter a job

Inspect the supported asset, intended audience, current awareness, channel
access/rules and useful next action. A discovery post can expose a recognizable
problem; an explanation can teach the tradeoff; a demo can establish mechanism;
a guide can help someone act. Do not restate the same inventory everywhere or
force every reader into checkout.

Example: a fictional review-history article already explains a version mistake.
A short post can show the mistake, the article can explain version boundaries,
and the existing guide can show supported recovery. A carousel is optional if
comparison benefits from visible steps; it is not owed to every article.

## Reuse the strongest available proof

Inventory what actually exists: published explanation, recorded behavior,
screenshot, code example, source evidence. Separate capture needed from captured
material. Choose a form that suits the encounter and evidence, not one requiring
invented testimonials or a new application feature. A local demo must keep local
truth and availability clear.

Recommend one primary context and useful supporting encounters where justified.
For each, give audience, distinctive job, asset reuse/adaptation, next action,
release owner and dependency. Use [channel strategy](channel-strategy.md) if the
platform choice is material. Respect community rules and audience relevance;
a generic cross-post kit is often worse than a useful contextual answer.

## Finish and learn proportionately

Writing gets argument, source artifact, preserved claims and requested medium.
Missing assets/rights return to the existing owner. Schedule, posting, outreach,
account access and paid promotion need separate authority. Drafting a release
plan does not distribute it.

Choose a signal tied to the encounter job: comprehension/replies for a lesson,
qualified guide visits for a task, or observed completion for a usable path.
Record actual denominators and attribution limits where available. Reactions
are not proof the audience understood or bought because of the asset. Reuse the
current task record and Taste feedback method; no promotion tracker or monitor
is required.
